WebAssembly · no plugin · no install

C apps that run in your browser

RayClay is a pure-C99 immediate-mode GUI library. Every demo below is the same C source that compiles to a native desktop window, rebuilt for the web with one command and no #ifdef. What you are about to click is not a video or a screenshot. It is the app. 

/* the whole program */
#include "rayclay.h"
int main(void) { return rcRunApp(NULL); }

$ cmake --preset web        # -> a page you can host anywhere

Everything at once : the gallery, the inspector and the monitor

ex10

Widget gallery

Every widget in the library on one page, plus live re-tintable icons: an icon's colour is just an argument you pass each frame.

 ex12

Live inspector

The library watching itself: a draggable split pane, live fps and frame-time charts, and a table log that follows its own tail, fed by RayClay's own diagnostics.

 ex20

System monitor

A sortable virtualized process table under live load charts, and a branded titlebar that folds to a drag rail on a keystroke. On the desktop that band carries the real window controls; here the browser tab is the chrome, so it draws and does nothing. Same source, one target doing less.

 ex21

Data explorer

An analytics workbench over a 12,000-row exoplanet catalogue. Filter from the rail and a year chart, a radius histogram, a scatter plot and a sortable 12,000-row table all follow: one dataset, many views, driven through an index array that never copies or reorders a single record.

 ex22

Documentation reader

The one example that ships its own typography: a real family ladder registered a weight at a time, a reading column held to a comfortable line length as the window resizes, and a table of contents that folds away when there is no room for it.

 ex23

Issue inbox

The rail / list / detail shape every desktop app is built on, over 100,000 issues. Type in the filter and the whole list re-selects; scroll it and about thirty elements are ever declared, because the cost of drawing is set by the window rather than by the dataset.

 ex24

SVG live

The same artwork drawn three ways at once: pointed at by path (rcSvg, one line in the layout, no state), drawn from a handle you loaded yourself, and compiled in from a generated header. They are indistinguishable on purpose: the choice is about your build, not about how it looks. Press Unload and only the handle you own goes away.

Resize the window; the layout reflows, because it is a real layout engine, not a scaled bitmap.
